# react-client-tenant

React hooks and headless components over the Contember **Tenant GraphQL API** (identity, authentication, projects, memberships, API keys, project secrets). This is the data layer that `react-identity` and `react-ui-lib-tenant` build on.

It is built on top of `@contember/graphql-client-tenant` — a fully typed client **generated from the engine's tenant SDL at build time** (`packages/graphql-client-tenant`, regenerated by its `pre-build`; the committed `src/generated` is just stubs). That generated client tracks the API by construction, so it is never the gap layer — real gaps live here (hand-written hooks/components) and in the UI package.

## GraphQL plumbing

- `useTenantApi(options?)` — returns an executor that runs a graphql-ts-client `Fetcher` against the tenant client (`useTenantGraphQlClient()` from `@contember/react-client`). Builds the query string from the fetcher DSL; resolves the auth token (`apiToken` / `LoginToken`).
- `useTenantMutation` / `createTenantMutation(fetcher)` — wrap a mutation fetcher and normalize the result into `TenantMutationResponse` (`{ ok: true, result } | { ok: false, error, developerMessage }`).
- `useTenantQueryLoader(fetcher, variables)` — drives a query hook through `loading → success/error → refreshing` states and exposes `refresh()`.

## Hooks

- **Queries** (`hooks/queries/`): `useMeQuery`, `useProjectMembersQuery`, `useProjectMembershipsQuery`, `useProjectRolesDefinitionQuery`, `usePersonsQuery`, `usePersonQuery` (single person by id, incl. sessions and identity providers), `useProjectApiKeysQuery`, `useGlobalApiKeysQuery`, `useProjectSecretsQuery`, `useMySessionsQuery` / `usePersonSessionsQuery` (own vs. admin-view sessions), `useAuthLogQuery` (paginated, filterable audit log), plus the **read-only configuration** queries `useConfigurationQuery`, `useAuthPoliciesQuery`, `useIdentityProvidersQuery`, `useMailTemplatesQuery` (no matching mutation hooks by design — the write path is `contember tenant:apply`).

**Permission failure is not uniform.** The listing queries return an empty result when the caller may not see anything; the four configuration queries **throw** a `ForbiddenError` instead. Use `isForbiddenError` (`types/forbidden.ts`) to tell a permission rejection from a real failure — matching `extensions.code === 'ForbiddenError'` on a `GraphQlClientError`, or the HTTP-level `forbidden` type.
- **Mutations** (`hooks/mutations/`, grouped by domain): `apiKey`, `auth` (incl. `useSignUpMutation`), `emailOtp` (init/confirm/disable e-mail OTP), `emailVerification`, `identity` (`useAddGlobalIdentityRolesMutation` / `useRemoveGlobalIdentityRolesMutation`), `idp`, `invite` (`useInviteMutation`, `useUnmanagedInviteMutation`), `memberships`, `otp` (incl. `useRegenerateBackupCodesMutation`), `passwordReset`, `passwordless`, `person` (`useDisablePersonMutation`, `useEnablePersonMutation`, `useForceSignOutPersonMutation`, `useResetPersonMfaMutation`, `useChangePasswordMutation` — admin sets a person's password directly), `profile`, `project` (`useSetProjectSecretMutation`), `session` (`useRevokeSessionMutation`).

Each hook defines a fragment with the `TenantApi.x$` / `x$$` fetchers, derives its result type via `ModelType<typeof fragment>`, and passes query arguments with `ParameterRef.of(...)`.

## Components

- **Form providers** (`components/forms/`): `TenantForm` plus per-flow wrappers — `LoginForm` (now with a `backupCode` fallback field alongside `otpToken`), `InviteForm`, `AddProjectMemberForm`, `CreateApiKeyForm`, `CreateGlobalApiKeyForm`, `UpdateProjectMemberForm`, `ChangeMyPasswordForm`, `ChangeMyProfileForm`, `ChangeProfileForm` (admin edits another person), `ChangePasswordForm` (admin sets another person's password), `PasswordReset*`, `VerifyEmailForm`, `EmailOtpConfirmForm`, `SetProjectSecretForm`, `PasswordlessSignIn*` (also with a `backupCode` fallback), `Otp*`, `SignUpForm` (open registration — creates the account, does **not** sign in), etc. `InviteForm` takes `allowUnmanaged` to let `values.unmanaged` route the submit through `unmanagedInvite` (no mail, optional password) instead of `invite`; off by default. Each exposes a `useXForm()` hook (a typed view of `useForm`) consumed by the field components in `react-ui-lib-tenant`. Form state is `FormContextValue<Values, ErrorCode>` (`values` / `errors` / `state` / `setValue`).
- **Identity** (`components/`, `contexts.ts`): `IdentityProvider`, `IdentityState`, and the `useIdentity` / `useIdentityMethods` / `useIdentityState` contexts; `useFetchIdentity`, `useLogout`.
- **Triggers** (`components/triggers/`): `DisableOtpTrigger`, `LogoutTrigger`, `RemoveProjectMemberTrigger`, `TenantActionTrigger`, plus one-shot admin/self-service triggers: `DisablePersonTrigger`, `EnablePersonTrigger`, `ForceSignOutPersonTrigger`, `ResetPersonMfaTrigger`, `RevokeSessionTrigger`, `RegenerateBackupCodesTrigger`, `InitEmailOtpTrigger`, `DisableEmailOtpTrigger`, `EnableMyPasswordlessTrigger`, `DisableMyPasswordlessTrigger`.
- **IDP** (`components/idp/`): `IDP`, `IDPInitTrigger`, `IDPState` + `useIDPState`.

## Public API surface

`react-client-tenant.api.md` (in `build/api`) is checked by the `api-exporter` CI job. After adding/removing exports, regenerate it with `bun run ae:update` and commit the diff.

See [tenant API reference](https://docs.contember.com/reference/engine/tenant/overview) for the underlying operations.
